# Windows testing — v0.9.1.15

1. Close old application instances before launching the new EXE.
2. From the extracted source directory, run `powershell -ExecutionPolicy Bypass -File .\BUILD-AND-RUN.ps1` (build, self-test, publish, and launch), or the full manual sequence below.
3. At Manual Review, watch **Preparing Manual Review** show the actual percent of artist checks completed. At 100% it should disappear. If the preflight has 0 pending checks it can finish immediately.
4. For source-complete artists with only one corresponding artist name (e.g. HOT SPOT, F4ST, Eiden XII), check that they no longer occupy the Artist Review queue. Repeat for several MB IDs resolving to a single identical artist name (e.g. Daniel Murphy).
5. Check that artists with genuinely different candidate names (e.g. distinct bands, tribute performers or mixed names) are not auto-verified. Cases with missing artist, song, album, or valid watch link must stay reviewable.
6. Open **Migration Preview → Saved for Manual Import**, find an automatically saved item, click **Review / Edit**, adjust its metadata, click **Save Manual Metadata**, and verify the updated entry is present in the saved list. This is how a user can revisit an entry.
7. Refresh during preflight; it should reconnect to the running server and not restart the full verification.
8. Confirm no Lidarr write/downloads happened. The matched totals must not rise merely because metadata was saved.

Manual PowerShell commands (stop if a command fails):

```powershell
dotnet build YouTubeMusicToLidarr.csproj -c Release -r win-x64
dotnet run --project YouTubeMusicToLidarr.csproj -c Release -r win-x64 --no-build -- --self-test
dotnet publish YouTubeMusicToLidarr.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish
.\publish\YouTubeMusicToLidarr.exe
```

**Do not throw away your old evidence CSVs or source ZIPs.** This release does not import the memory of a separately running EXE; a new application process may still require a fresh verification run.
