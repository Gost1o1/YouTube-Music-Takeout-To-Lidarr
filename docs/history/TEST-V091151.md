# Windows test instructions — v0.9.1.15.1

1. Close older running copies of the application.
2. Extract this entire ZIP into **a new folder**. Do not merge into v0.9.1.15.
3. In PowerShell from the extracted root run:

```powershell
powershell -ExecutionPolicy Bypass -File .\BUILD-AND-RUN.ps1
```

This does all four steps and stops on an error: **build → application self-tests → self-contained win-x64 publish → launch**.

Alternatively, full commands:

```powershell
dotnet build YouTubeMusicToLidarr.csproj -c Release -r win-x64
dotnet run --project YouTubeMusicToLidarr.csproj -c Release -r win-x64 --no-build -- --self-test
dotnet publish YouTubeMusicToLidarr.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish
.\publish\YouTubeMusicToLidarr.exe
```

4. Verify the build no longer reports CS0103 in `GuidedReviewV917.cs`, and check that the Manual Review screen lists manual overrides without errors.
5. Confirm the **Saved for Manual Import → Review / Edit** path remains available, and refreshing does not restart the scan.

Offline developer check (requires Python and Node, not needed for normal Windows use):

```powershell
python tools/check_v091151_restored_scope.py
node --check AppUI/flow918.js
node tools/offline_v09115_preflight_restore.js
```

Do not discard your existing exports or original Takeout archive. This hotfix does not itself perform Lidarr writes or downloads.
