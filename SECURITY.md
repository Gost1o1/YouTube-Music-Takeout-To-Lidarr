# Security notes — v0.9.1.15.9 preview

- This is development-only software; no independent security audit or Defender clearance has been completed.
- The local HTTP server listens on loopback, checks the request host/origin, and uses a random per-launch API session token. The Lidarr key remains in process memory and is never deliberately sent to outside metadata providers.
- When the user starts verification, catalog research may send relevant song and artist strings to MusicBrainz, Apple/iTunes and Deezer. In this version, optional review artwork and preview lookup starts **automatically during the matching pipeline's Lidarr-comparison phase**, before the user opens Manual Review. YouTube oEmbed lookups can send the original video URL back to YouTube. These providers' privacy policies/terms apply. The Takeout ZIP and Lidarr API key are not transmitted to those metadata providers.
- Local audit report imports require matching Takeout row identities and never modify the original Takeout ZIP. They are not treated as freshly verified MusicBrainz matches.
- Matching, review, and Migration Preview are read-only for Lidarr. **Only the final, explicitly approved import action writes to Lidarr:** it can add independently verified artists, monitor selected albums, and optionally request album searches after separate consent. A search can download an entire album. No Lidarr delete endpoint is used by this importer.
- The application never synthesizes audio files from source-only metadata, and a queued Lidarr command does not prove that a song was downloaded. The Windows download needs no end-user PowerShell script; the source package includes a developer-only build script. Never disable security tools to run the app.
- Temporary diagnostic logging may include artist titles; do not publish private audit CSVs, music metadata, keys, logs or reports to GitHub.
- App-managed files are written only under the portable EXE's `RunData` directory (a diagnostic log, review decisions, manual metadata and an import checkpoint). Normal shutdown removes these exact app-owned files. If a write or catalog check is unexpectedly interrupted, the checkpoint remains under the same EXE folder for safe reconciliation. An abrupt process termination may also leave other session files that a later successful exit cleans. No API key is saved.
- During the first launch from a legacy installation, the app may read and copy three specific prior state files from `Documents\MusicTakeoutToolkit` so users do not unexpectedly lose hundreds of review decisions. It does not modify or delete the old originals. See the data-locations document for details.
- The app tab uses a random per-tab identifier for a loopback-only heartbeat. Closing the last tab triggers process exit after a safety grace period, but an active Lidarr write or catalog check is allowed to complete first. This version still displays the developer console.
