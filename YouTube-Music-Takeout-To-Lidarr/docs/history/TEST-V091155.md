# v0.9.1.15.5 test plan

## Automated checks

Run `node tools/offline_v091155_review_progress_provenance.js` after the
eight existing offline UI regression tests.

The new fixture verifies:

1. Manual artist approval updates the Artist Matching progress count.
2. The last Artist Review Next button switches to Song Review.
3. Manual song review and automatic source-only song filing update the Song
   Matching addressed and remaining counts without implying verification.
4. A song eligible for automatic filing never renders a YouTube source card.
5. Manually selected and automatically source-filed songs appear under
   **To Be Added**, with correct origin labels, and not under **Unmatched**.
6. Only unresolved rows remain under **Unmatched**.
7. No Lidarr staging/write API is invoked by these review/preview actions.

## Live Windows test

- Verify the application shows `v0.9.1.15.5` in its upper-right corner.
- Restore prior song/artist audits instead of repeating a long 2,505-song
  verification scan if suitable matching files are available.
- Review one artist and verify its bar updates immediately. The last artist
  should take you to the first remaining song automatically.
- Observe a source-complete, automatically saved song: it should be hidden
  while preparing/saving, then disappear from the queue and increment
  the addressed count once.
- Open Migration Preview and confirm the three origin tags and their categories.
  The **Saved for Manual Import** tab must still contain editable source-only
  records and the ordinary album selection controls must still work.
- Confirm no Lidarr download or add is initiated.

Run the GitHub Actions Windows build and built-in `--self-test` before
distributing this ZIP or publishing a GitHub Release. The local tests cannot
replace a real Windows compile.
