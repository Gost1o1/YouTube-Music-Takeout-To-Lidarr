# Windows build instructions — v0.9.1.13.1

Extract the entire ZIP to a **new folder**. Do not merge with the broken v0.9.1.13 folder. Close older versions of the application before launching the new executable.

## One command to do everything

Open PowerShell in the extracted folder and run:

```powershell
powershell -ExecutionPolicy Bypass -File .\BUILD-AND-RUN.ps1
```

The script builds the app, runs its native self-tests, publishes the standalone self-contained EXE, and launches it. It stops immediately on any build, self-test, or publish failure.

## Or all commands separately

```powershell
dotnet build YouTubeMusicToLidarr.csproj -c Release -r win-x64
dotnet run --project YouTubeMusicToLidarr.csproj -c Release -r win-x64 --no-build -- --self-test
dotnet publish YouTubeMusicToLidarr.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish
.\publish\YouTubeMusicToLidarr.exe
```

For the separate commands, **stop if a step fails**; do not continue publishing or launching an out-of-date build.

## Expected manual-import behavior

When an unresolved artist/song entry has valid original source metadata but no usable MusicBrainz candidates, it should be saved to the separate **Saved for Manual Import** summary and removed from the interactive review queue. It should NOT be treated as a verified MusicBrainz match or a downloaded Lidarr file. Verify that Manual Review can advance after a manual save and that refresh restores the user's navigation.
